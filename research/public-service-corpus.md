## 5. KRDS Crosswalk

실제 사례를 수집할 때 아래 KRDS 컴포넌트 축으로 같이 태깅한다.

| 컴포넌트 | 수집 질문 |
|---------|----------|
| Button | 버튼만 보고 결과를 예측할 수 있는가 |
| Text input / Select | 레이블과 플레이스홀더가 역할을 섞지 않는가 |
| Search | 검색 도움말과 무검색 결과가 있는가 |
| Modal / Confirm | 비가역 행동 전에 경고와 다음 행동이 분리되는가 |
| Banner / Notice | 법적 고지가 결론 우선 구조를 따르는가 |
| Table / Result | 상태·기한·후속 행동을 한눈에 읽을 수 있는가 |

## 6. Promotion Rule

아래 조건을 만족하면 사례를 원칙 본문으로 승격한다.

- 3개 이상 대표 사이트에서 반복된다.
- 제출·납부·자격 판정처럼 실수 비용이 큰 화면이다.
- 특정 KRDS 컴포넌트에서 반복되는 실패 패턴이다.
- 법적 필수 문구를 유지하더라도 보조 설명 없이는 이해가 무너진다.

## 10. Recommended Sweep Method

대표 사이트 순회는 "한 사이트를 깊게 본다"보다 "같은 단계로 여러 사이트를 반복해서 본다"가 더 효율적이다.
한 번의 순회는 다음 순서로 운영한다.

1. 사이트 8개를 같은 순서로 연다.
2. 각 사이트에서 검색, 자격/조건, 입력, 오류, 완료, 상태, 법적 고지 중 1~2단계만 본다.
3. 각 화면에서 원문 표현 3개, CTA 1개, 상태/기한/경로/담당 기관·관할/대리 가능 대상·권한 범위·해지 경로/신청인 유형/긴급 연락처/병행 절차/공백 없는 복합어 메뉴명 정보 1개를 수집한다.
4. 각 발견 사항에 KRDS 컴포넌트 태그를 붙인다.
5. 즉시 `사전 후보 / 사례 카드 / 원칙 승격 / 6장 Layer 3 유지` 네 갈래 중 하나로 분류한다.
