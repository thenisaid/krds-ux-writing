UI 컴포넌트 라이팅
(Component Microcopy)

컴포넌트마다 공식이 있다

대표 사이트 순회에서 반복되는 버튼·검색·세션 종료·상태표·발급 결과·완료 뒤 후속 흐름을 12개 KRDS 컴포넌트와 조합 규칙으로 다시 정리합니다. 이 장은 사례 승격 기준과 KRDS에 바로 붙일 수 있는 운영 공식을 남깁니다. 새 실화면은 새 CASE 번호보다 기존 CASE 묶음과 Description handoff부터 정합니다.

개요

UI 컴포넌트는 시민이 공공 서비스와 직접 상호작용하는 접점입니다. 각 컴포넌트에 최적화된 마이크로카피 공식을 적용하면 오조작·이탈을 줄이고 완료율을 높입니다. 정부24·복지로·국민신문고·고용24·서울시 응답소의 반복 패턴을 KRDS 컴포넌트 기준으로 다시 정리했습니다.

컴포넌트핵심 원칙
4.1 버튼과업 명사 + 결과 동사, 최상위 강조 버튼 1개, 판단 뒤 바로 실행 CTA
4.2 입력 폼레이블+플레이스홀더+안내문 3중 구조, 계산 기준·제외 조건·예상값 변동 변수 선공개
4.3 선택지이중부정 금지, 동의 항목 묶기, 분기별 준비물·경로·추가 서류·조건부 필수·증명서 종류·등급별 차이·예상 비용 선공개
4.4 모달·토스트원인+해결책, 세션 종료는 저장·재진입 동시 안내
4.5 아코디언·툴팁맥락 유지 인라인 헬프
4.6 빈 화면원인+대안버튼 필수, "내역 없음" 금지
4.7 단계 표시기"Step N/총N. 섹션명" 형식
4.8 태그·배지4음절 이내, 상태값 위계 준수
4.9 검색창예시 플레이스홀더 + 역할별 컨트롤 이름
4.10 탭MECE 분류 원칙
4.11 표·데이터 그리드헤더도 시민 언어로, 빈칸은 명시적으로 처리
4.12 배너·인라인 경고상태 1줄 + 행동 1개, 완료·기한·알림 채널 정보 선공개
실제 사례 추가 시작 메모: 새 실화면은 바로 새 CASE 번호로 만들지 않습니다. 먼저 이슈 아카이브와 기존 CASE 묶음에서 비슷한 실패를 찾고 원문 3개+CTA 1개, UX/UI 검수 축 1개, KRDS 조합 1개를 적습니다. 7장에서는 CASE 39·37·9, CASE 10·49, CASE 16, CASE 4·5·13·27 가운데 먼저 붙일 묶음을 고르고, 세 대표 사이트 반복이면 Description, 기본 예시 문구, 숨은 레이블 메모까지 같은 라운드에서 KRDS/Figma handoff로 넘깁니다. 기관 고유 제도면 6장 Layer 3 메모로 보류합니다.
KRDS 연결 빠른 참조 — 단일 컴포넌트보다 조합 규칙을 먼저 정한다

공공 서비스 화면은 버튼 하나, 배너 하나로 끝나지 않습니다. 같은 과업 안에서 어떤 KRDS 컴포넌트를 묶어야 시민이 판단 → 입력 → 실행 → 후속 처리를 끊기지 않고 이해하는지 먼저 정해야 합니다. 이 표는 실제 공공서비스 화면을 빠르게 재구성할 때 쓰는 조합 기준입니다.

표기 QA를 7장 KRDS/Figma handoff로 넘길 때 바로 적는 메모
