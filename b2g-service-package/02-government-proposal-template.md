## 1. 제안 개요

### 1.1 사업 배경

[기관명]은 「행정안전부 디지털 서비스 기본 지침」 및 KRDS(한국 디자인 시스템) 고시에 따라 디지털 서비스의 사용성 향상 의무를 이행하고 있습니다. 현행 서비스의 문구·레이블·안내문은 행정 용어 중심으로 작성되어 있어, 시민의 인지 부하와 민원 발생 요인이 되고 있습니다.

본 사업은 KRDS 기반 UX Writing 전문 방법론을 적용하여 [기관명] 디지털 서비스의 접근성과 사용성을 제고합니다.

### 1.2 사업 목적

- **명확성**: 행정 언어를 시민 언어로 전환하여 서비스 이해도 향상

- **접근성**: KWCAG 2.1 AA 기준 준수 (인지·언어 접근성)
- **지속성**: 기관 자체 운영 가능한 UX Writing 가이드라인 수립

## 4. 수행 방법론

### 4.1 전체 프로세스

```
[1단계] 현황 분석
  ├── 서비스 전체 문구 수집 (크롤링 + 수동 캡처)
  ├── KRDS 컴포넌트 매핑
  └── 우선순위 문제 도출

[2단계] 기준 수립
  ├── 보이스 앤 톤 정의 (기관 성격 반영)
  ├── 핵심 작성 원칙 설정 (3원칙)
  └── 컴포넌트별 작성 규칙 초안

[3단계] 문구 개선 작성
  ├── 우선순위 순 마이크로카피 재작성
  ├── Do / Don't 예시 문서화
  └── 담당자 리뷰 및 피드백 반영

[4단계] 검증 및 납품
  ├── KWCAG 2.1 체크리스트 검증
  ├── 최종 산출물 납품
  └── 담당 공무원 인수인계 교육
```

### 4.2 KRDS 컴포넌트 기반 마이크로카피 작성 원칙

| 컴포넌트 | 작성 원칙 | 예시 |
|---------|---------|------|
| Button (Primary) | 동사 + 목적어, 3단어 이내 | "신청서 제출" (O) / "확인" (△) |
| Input Label | 명사형, 필수 여부 명기 | "이름 (필수)" |
| Input Placeholder | 입력 형식 안내 | "홍길동 (실명으로 입력)" |
| Error Message | 원인 + 해결 방법 | "이메일 형식이 맞지 않아요. '@'를 포함해 다시 입력하세요." |
| Toast / Alert | 결과 + 다음 행동 | "신청이 완료됐어요. 마이페이지에서 확인하세요." |
| Empty State | 상황 설명 + 행동 유도 | "아직 신청 내역이 없어요. 첫 신청을 시작해보세요." |
| Loading | 진행 상황 안내 | "조회 중입니다. 잠시만 기다려주세요." |

### 4.3 쉬운 정부 언어 적용 기준

| 규칙 | 적용 기준 |
|------|----------|
| 14세 기준 무번역 원칙 | 중학교 2학년이 이해 가능한 어휘 사용 |
| 문장 길이 | 1문장 35자 이내 권장 |
| 능동태 우선 | "처리되었습니다" → "처리했습니다" |
| 한자어 최소화 | "기재" → "입력", "접수" → "신청" |
| 경어 통일 | 전체 "-요" 체 (존댓말 통일) |
