## SOW-A: UX Writing 감사형

### 사업 개요

| 항목 | 내용 |
|------|------|
| SOW 유형 | 감사 (Audit) |
| 대상 서비스 | [서비스 URL 및 범위] |
| 수행 기간 | [시작일] ~ [종료일] ([N]주) |
| 계약 금액 | [금액]원 (부가세 포함) |

### 수행 범위 (Scope of Work)

**을(수행기관)은 다음 업무를 수행합니다:**

1. **서비스 현황 수집**
   - 대상 서비스 전체 화면 목록화 (화면 ID, URL, 스크린샷)
   - 주요 사용자 여정(User Journey) 기준 화면 분류

2. **UX Writing 감사 수행**
   - KRDS 컴포넌트 기반 마이크로카피 점검 (14종 컴포넌트)
   - 쉬운 정부 언어 기준 위반 항목 식별
   - KWCAG 2.1 언어 접근성 항목 검증
   - 심각도 분류 (Critical / Major / Minor)

3. **개선 리포트 작성**
   - 문제 현황 요약 (심각도별 통계)
   - 우선순위 개선안 제시 (상위 20개 항목 상세 개선안 포함)
   - 나머지 항목 방향성 가이드

4. **최종 보고 및 인수인계**
   - 최종 보고 미팅 진행 (온/오프라인 선택)
   - 담당자 질의응답 및 활용 방법 안내

### 산출물 (Deliverables)

| 번호 | 산출물 | 형식 | 납품 기한 |
|------|-------|------|----------|
| D-1 | 화면 목록 (인벤토리) | Excel | [N주차] |
| D-2 | UX Writing 감사 리포트 | HWP + PDF | [N주차] |
| D-3 | 우선순위 개선안 문서 | HWP + PDF | [N주차] |
| D-4 | 최종 보고 자료 | PPT + PDF | [최종 보고일] |

### 완료 조건 (Acceptance Criteria)

- [ ] 대상 화면의 95% 이상 점검 완료
- [ ] 심각도별 문제 항목 목록 제공 (Critical 항목 100% 개선안 포함)
- [ ] KWCAG 2.1 체크리스트 작성 완료
- [ ] 갑(발주기관)의 서면 수령 확인

### 대금 지급 조건

| 잔금 | 최종 산출물 납품 및 갑 수령 확인 시 | 30% |

## SOW-B: 가이드라인 납품형

### 사업 개요

| 항목 | 내용 |
|------|------|
| SOW 유형 | 가이드라인 수립 및 납품 |
| 적용 서비스 | [서비스명 및 범위] |
| 수행 기간 | [시작일] ~ [종료일] ([N]주) |
| 계약 금액 | [금액]원 (부가세 포함) |

### 수행 범위 (Scope of Work)

**을(수행기관)은 다음 업무를 수행합니다:**

1. **현황 분석 및 기준 설정**
   - 기관 디지털 서비스 현황 파악
   - 기관 특성 반영 보이스 앤 톤 정의 (워크숍 1회 포함)
   - 핵심 작성 원칙 도출 (기관 미션·가치 연계)

2. **가이드라인 본문 작성**
   - 보이스 앤 톤 가이드 (정의, 상황별 적용 예시)
   - 핵심 작성 원칙 (3~5개 원칙, Do/Don't 각 10예시)
   - KRDS 컴포넌트별 마이크로카피 작성 규칙 (14종)
     - Button / Input / Form / Alert / Toast / Modal / Badge
     - Navigation / Empty State / Loading / Error / Tooltip
     - Stepper / Notification
   - 금지어·권장어 목록 (100단어 이상)

3. **검토 및 확정**
   - 내부 검토 (을 자체 QA)
   - 갑 담당자 검토 및 피드백 반영 (2회 이내)
   - 법적 표현·행정 용어 전문가 검토 (선택 사항)

4. **납품 및 교육**
   - 최종 가이드라인 납품 (HWP, PDF, 편집 가능 버전)
   - 담당 공무원 교육 세션 (4시간, 실습 포함)
   - 활용 가이드 문서 제공

|------|-------|------|----------|
| D-1 | 착수 보고서 | HWP + PDF | [착수 후 1주] |
| D-2 | 보이스 앤 톤 정의서 (초안) | HWP | [N주차] |
| D-3 | 가이드라인 초안 v0.1 | HWP + PDF | [N주차] |
| D-4 | 가이드라인 v1.0 (최종) | HWP + PDF + DOCX | [납품 기한] |
| D-5 | 컴포넌트별 마이크로카피 예시집 | Excel | [납품 기한] |
| D-6 | 교육 자료 | PPT + PDF | [교육일] |
| D-7 | 금지어·권장어 사전 | Excel + PDF | [납품 기한] |

### 완료 조건 (Acceptance Criteria)

- [ ] KRDS 컴포넌트 14종 전체 커버
- [ ] Do/Don't 예시 컴포넌트당 최소 3쌍 이상
- [ ] 금지어·권장어 100개 이상 포함
- [ ] 교육 세션 완료 및 참석자 서명부 제출
- [ ] 갑의 서면 수령 확인

| 중도금 | 가이드라인 초안 제출 후 갑 확인 시 | 40% |

## SOW-C: 서비스 문구 개편형

### 사업 개요

| 항목 | 내용 |
|------|------|
| SOW 유형 | 서비스 문구 전면 개편 |
| 대상 서비스 | [서비스명 / URL / 화면 수] |
| 수행 기간 | [시작일] ~ [종료일] ([N]주) |
| 계약 금액 | [금액]원 (부가세 포함) |

### 수행 범위 (Scope of Work)

**을(수행기관)은 다음 업무를 수행합니다:**

1. **킥오프 및 현황 파악**
   - 킥오프 미팅 (발주기관 담당자, 개발팀, 디자인팀 참석 요청)
   - 화면 인벤토리 작성 (전체 화면 목록화)
   - 현행 문구 수집 (스프레드시트 정리)

2. **마이크로카피 재작성**
   - 전체 화면 문구 재작성 (우선순위 기준)
   - KRDS 컴포넌트 매핑 (컴포넌트별 문구 분류)
   - 수정본 v1.0 → 갑 리뷰 → v2.0 (최대 2회 수정)

3. **QA 및 검증**
   - KWCAG 2.1 언어 접근성 검증 (전수 체크)
   - 일관성 검증 (동일 개념 동일 표현 확인)
   - 최종 교정·교열

4. **납품 및 지원**
   - 전체 문구 수정본 납품 (개발 적용용 스프레드시트)
   - 개발팀 인수인계 (1회 미팅)
   - 납품 후 30일 이내 발견된 오탈자·오기 무상 수정

## SOW-D: 교육·훈련 워크숍형

### 사업 개요

| 항목 | 내용 |
|------|------|
| SOW 유형 | 교육·훈련 워크숍 |
| 과정명 | [기초 / 심화 / 실무 프로젝트] 과정 |
| 교육 일시 | [날짜] [시간] ~ [시간] |
| 교육 장소 | [장소 또는 온라인] |
| 참가 인원 | [N]명 (최대 30명) |
| 계약 금액 | [금액]원 (부가세 포함) |

### 수행 범위 (Scope of Work)

**을(수행기관)은 다음 업무를 수행합니다:**

1. **사전 준비**
   - 기관 서비스 현황 파악 및 교육 자료 커스터마이징
   - 실습 자료 제작 (기관 서비스 기반 예시 포함)
   - 참가자 사전 설문 (선택 사항, 갑 요청 시)

2. **교육 진행**
   - 이론 강의 (UX Writing 원칙, KRDS 컴포넌트 기반 작성법)
   - 실습 워크숍 (기관 실제 화면 기반 개선 실습)
   - Q&A 세션

3. **과정별 커리큘럼**

   **기초 과정 (4시간)**
   | 시간 | 내용 |
   |------|------|
   | 0:00 ~ 0:30 | UX Writing이란? 왜 정부 서비스에 필요한가 |
   | 0:30 ~ 1:30 | 쉬운 정부 언어 핵심 원칙 (이론 + 예시) |
   | 1:30 ~ 2:00 | KRDS 컴포넌트별 작성 기준 |
   | 2:00 ~ 3:30 | 실습: 현행 문구 개선 (조별 작업) |
   | 3:30 ~ 4:00 | 발표 및 피드백 / Q&A |

   **심화 과정 (8시간)**
   | 시간 | 내용 |
   |------|------|
   | 0:00 ~ 1:00 | 기초 복습 + 심화 원칙 |
   | 1:00 ~ 2:30 | 오류 메시지·안내문·온보딩 심화 작성법 |
   | 2:30 ~ 3:00 | 접근성 관점의 UX Writing (KWCAG 기준) |
   | 3:00 ~ 4:00 | 점심 |
   | 4:00 ~ 5:30 | 실습: 전체 서비스 문구 개선 프로젝트 (조별) |
   | 5:30 ~ 6:30 | A/B 테스트·사용자 검증 기초 |
   | 6:30 ~ 7:30 | 조별 발표 및 피드백 |
   | 7:30 ~ 8:00 | 마무리 Q&A + 학습 자료 공유 |

4. **사후 관리**
   - 교육 자료 PDF 배포 (참가자 전원)
   - 수료증 발급 (갑 요청 시)
   - 교육 후 30일 이내 질의응답 채널 운영 (이메일)

| D-2 | 실습 워크북 | PDF | 교육 당일 |

### 요청 처리 프로세스

```
[갑] 요청 접수 (이메일 / 협업 채널)
    ↓
[을] 접수 확인 + 유형 분류 (긴급 / 일반)
    ↓
[을] 초안 작성 → 갑 검토 요청
    ↓
[갑] 피드백 (2영업일 이내)
    ↓
[을] 최종본 납품
    ↓
[갑] 수령 확인 → 처리 건수 기록
```
